## 为什么变（现状 → 目标的差距本质）

项目愿景是「AI 无人值守全自动出 3D 机械图」。三期 17/17 + 四期 N18-N21 把能力面（零件→装配→工程图→PDF/STEP/STL/DXF 全链路 69 工具）和治理面（12 个 ADR、双仓 AGENTS.md、计划台账）都闭环了。按四期计划自己的核心判断：剩余差距全部是「治理与可靠」而非「能力缺失」。本审查证实该判断，并把「可靠」里的最大一块提升为新发现：

1. **G1 交付可靠（新发现，P0）**：主仓 origin 停在 04bf21f（T21 钣金），其后 N8-N14 六大特性 + N18-N21 共 **15 个提交从未推送**；aicad 子仓 **69 个提交零远端**；主仓 ci.yml 是 GitHub Actions 语法但远端在 gitee——**CI 从未跑过**。任何磁盘故障 = 两周工作归零。
2. **G2/G3 质量观测**：N23 perf 预算负载敏感假红待空闲机复验（红线：禁放室断言）；aicad 前端零测试（最终交付物视觉正确性无自动防线）；缓存命中率有数据无报表；CodeRabbit 外审未 auth。
3. **G4-G7 能力长尾（远期）**：零件（loft/sweep/筋/圆顶/参考几何）、图纸（爆炸图/BOM 气泡）、CSG 契约 v2（v1 仅 4-op）、原生阵列升级（当前数学重建非参数联动）。
4. **G8 智能自治层（远期）**：plan-then-execute、RAG、mate 求解器、多模型路由——从「AI 可调用工具链」到「无人值守自主完成」的最后一层。

**S0 灾备保险（用户一次 `git push`，分钟级）→ S1 交付闭环（aicad 远端 + 双仓 CI）→ S2 质量收口 → S3/S4 能力长尾并行 → S5 智能自治。**
