# G10 多机部署评估备忘（N51，2026-09-10）

> **性质：只评估不实施**（第九期 N51，product-vision G10 数据输入）。
> 场景：车间/团队多台 SolidWorks 工位共用本产品。

## 1. 现状架构盘点（单机基线）

| 组件 | 形态 | 多机契合度 |
|---|---|---|
| 主仓 SolidWorksMCP | stdio MCP server，每客户端一个进程，COM 附着**本机** SW | **天然按席位复制**——每个工位装一份（frozen 包 47MB）即得 N 席 |
| aicad 后端 | 本地 FastAPI（127.0.0.1:8600），会话/批量队列**内存态**，沙箱本机 build123d | 单机设计；集中化有明确缺口（下表） |
| 前端 | 本地静态产物（Vite build） | 随 aicad 部署 |

## 2. 差距矩阵（集中化场景才命中）

| 维度 | 现状 | 集中化所需 | 量级 |
|---|---|---|---|
| SW 连接拓扑 | COM 必须与 SW 同机——**这是硬约束**（DCOM 远程 COM 未验证且工业界少用） | SW 相关操作只能下放到各席位；中心只做编排 | 架构级 |
| 会话持久化 | 内存（重启丢队列，N44 声明） | 外置存储+断点续跑 | M |
| 多租户/认证 | API token 可选（F2），无用户概念 | 认证+配额+隔离 | M |
| 批量队列 | 串行 worker×1，内存 | 跨机队列（每席位一个执行 agent + 中心派发） | L |
| 文件传递 | ALLOWED_ROOT 本地沙箱 | 工件回传（交付包 zip 已是聚合单元，天然适合） | S-M |
| SW 许可 | 每席位一个正装 SW | 不变（COM 自动化不绕许可） | — |

## 3. 结论与建议路径

1. **近期（零架构改动）**：**按席位部署**——每工位 frozen 主仓包 + 本机 SW + 本地 MCP 客户端。
   多席位即 N 份单机，今天的产物（N48/N49）直接支撑。集中共享的只有知识性资产
   （示例库/手册/评测集）——git 仓库分发即可。
2. **中期（若有真实诉求）**：中心化 aicad 编排（队列+会话持久化+认证），SW 操作经
   席位 agent 下发——G3 批量队列的内存 v1 已把「诚实状态机+交付包聚合」跑通，
   是中心化的原型；但**未见真实多机需求前不立项**（产品原则：不为想象中的规模付复杂度）。
3. **不评估项**：远程 COM（DCOM）/云 SW——超出桌面工位场景。
