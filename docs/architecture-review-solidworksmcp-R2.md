## B. 增量面深审（用户未提交工作，779 行）

### B.1 能力面（工具 25→27）

- **`solidworks_part_create_cone`**：底径/顶径/高的圆台（drafted extrusion）；draft 角 `atan2(|r_top−r_bottom|, h)` 弧度制、`Ddir1` 语义——**实机契约已探针验证**（sketch.py 注释引用 aicad channel-B，体积精确核对）
- **`solidworks_part_cut_threaded_hole`**：ISO 273 中等配合底孔径 + ISO 724 粗螺距（M2-M20，THREAD_SPECS 单源）；孔=底孔径圆柱 cut，螺纹=best-effort 装饰线（InsertCosmeticThread2，17 档法向偏移扫选边，45° 对角点取边）；**诚实降级**：未盖上时返回 warning 而非失败
- **execute_design_plan 新 ops**：cone / threaded_hole(+alias thread_hole) / annular_pattern(+alias ring_pattern)；annular 延迟导入避免 design↔pattern 循环依赖（处理正确）
- capabilities 的 plan 示例与 limitations 同步更新（自动派生的工具列表无需改 ✓）

### B.2 实机几何修正（本轮最重要的变更）

**孔平面语义修正**（design.py `HOLE_PLANE_ALIASES`）：R1 及之前的 `cut_round_hole`/annular pattern 把 `plane="top"` 解析到 SW 原生 Top Plane（Y 法向草图）→ **孔从侧面穿透板件**。实机探针证据（tools/probe_hole_plane_context.py，OCP/OCCT 面级分析）：请求的 top 孔落在 y=+40 侧面、6 个阵列孔中 4 个完全脱靶。修正后 "top" 重映射为 Front Plane 草图（+Z 面），与本仓全部 boss 的 +Z 生长约定一致；pattern.py 同步切换（cut 语义）。

### B.3 攻方复核结论（对 R1 刚落地的整改）

1. **file_close 半收口实锤**：R1 的 P2-8 修复在 mock 测试全绿下交付，实机却必失败（void 返回 None → `if not closed` 恒真）。R2 判定：**mock 测试虚构了返回值契约**——与"Mock 真值陷阱"同族但更隐蔽（不是 mock 意外真值，是测试主动设定了不存在的真值）。用户实机轮抓出并修复。**教训：void 型 COM 方法的测试契约必须按"无返回值+异常即失败"建模。**
2. **annular pattern 的平面语义**：R1 交付时 ADR-0007 声明"plane 语义同 cut_round_hole"——这句话本身成立，但两者共有的语义在实机上是**错的**（侧钻）。89% 覆盖率+全绿没有拦住，因为 mock 模型没有几何。**教训：几何语义正确性只能由实机或解析几何断言（如 ±2% 体积窗）守卫，mock 覆盖率不背这个锅。**
3. 其余 R1 防线（路径安全链、计数契约、会话过滤、timeout 机制）本轮增量**正确复用未绕过**（diff 通读 + cone save 链路实证）。
